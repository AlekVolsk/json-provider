# Отображение в DTO — типизированные объекты

У одного и того же хендла `table()` две поверхности для записей, выбор — по имени метода:

- **объектные методы** — `insert`, `update`, `selectAll`, `selectOne` — говорят типизированными DTO;
- **`*ByArray`-двойники** — `insertByArray`, `updateByArray`, `updateByIdByArray`, `selectAllByArray`, `selectOneByArray` — говорят сырыми записями `array<string,null|scalar>` и доступны всегда.

Массивная поверхность — фундамент (вся остальная документация использует её); DTO-отображение — адаптер поверх. Хранение, схема и валидация не меняются: DTO разворачивается в запись при записи и собирается из неё при чтении.

## Объявление DTO

DTO — обычный иммутабельный `final`-класс. Единственная точка связи с библиотекой — атрибут `#[JsonProviderRecord]` с именем таблицы: это чистые метаданные, они не влияют на финальность и иммутабельность. Типы колонок **не переобъявляются**: их знает схема, PHP-тип свойства лишь говорит, в каком виде нужно значение в коде.

```php
use AV\JsonProvider\Mapping\Attribute\JsonProviderRecord;

#[JsonProviderRecord('users')]
final class User
{
    public function __construct(
        public int $id,
        public string $email,
        public ?int $age,
        public StatusEnum $status,            // backed enum
        public \DateTimeImmutable $createdAt, // колонка datetime
    ) {}
}
```

Отображаются только промо-параметры конструктора **любой видимости** (`public`, `protected`, `private`) — значения читаются через замыкание, привязанное к области класса, поэтому non-nullable `private`-свойство с непустым значением не даёт ложный `NullNotAllowed`. Унаследованные `private`-свойства родительского класса не поддерживаются — маппируемое свойство объявляется на самом DTO. Колонки, которых нет в DTO, подчиняются правилам массивного ядра (пропуск nullable → `null`, пропуск non-nullable → ошибка на insert). Чтение — без рефлексии на строку: карта (и её reader-замыкание) компилируется один раз при регистрации.

Тип каждого маппируемого свойства обязан быть одиночным именованным: untyped, `union`, `intersection` и `mixed` отклоняются на компиляции с точным сообщением (`JsonProviderMappingException`).

## Регистрация

Привязывайте класс после того, как его таблица создана. Таблица берётся из атрибута, так что карта `table => class` руками не пишется:

```php
$db->registerDto(User::class, Order::class);
```

Регистрация **сразу компилирует и валидирует** DTO против схемы — имя свойства↔колонки, PHP-тип ↔ тип колонки, nullability и бэкинг enum должны совпадать. Любое несоответствие бросает `JsonProviderMappingException` здесь, а не на первом запросе.

## Соответствие типов

| Тип колонки | Тип свойства DTO |
| - | - |
| `string` / `int` / `float` / `bool` | тот же скаляр (`int` расширяется в `float`-свойство) |
| `date` / `time` / `timez` / `datetime` / `datetimez` | `\DateTimeImmutable` |
| `year` / `month` / `day` | `int` |
| `int` или `string` под enum | `BackedEnum` с совпадающим бэкингом |
| `<type>\|null` | nullable-свойство `?T` |

Temporal-колонки становятся настоящими объектами `DateTimeImmutable`; конвертация часового пояса — та же, что в массивном API: `datetime`/`datetimez` хранятся в UTC и отдаются в локальном поясе, а `date`/`time`/`timez` — verbatim (wall-clock), см. [Модель схемы → Типы даты/времени](04-schema-model.md#типы-датывремени-и-часовые-пояса).

При записи объект `DateTimeImmutable` **усекается** (не округляется) до точности колонки: `time`/`datetime` — до секунды, `timez`/`datetimez` — до миллисекунды. Это отличие от массивного API, где строка с лишней дробью отвергается (`TemporalFractionUnsupported`): у объекта из `new \DateTimeImmutable()` микросекунды есть почти всегда, и требовать их ручной обрезки было бы неудобно. Если потеря дроби важна — используйте `datetimez`/`timez` либо проверяйте значение до записи.

## Имена — snake_case ↔ camelCase

По умолчанию свойство отображается на snake_case-форму своего имени, с корректным разбиением аббревиатур: `createdAt` → `created_at`, `userID` → `user_id`, `HTTPStatus` → `http_status`, `APIKey` → `api_key`. Для обычного случая атрибут не нужен. `#[JsonProviderColumn("...")]` — штатный escape-hatch, когда имя колонки стратегией не выводится (действительно нерегулярное):

```php
use AV\JsonProvider\Mapping\Attribute\JsonProviderColumn;

public function __construct(
    #[JsonProviderColumn('legacy_title')]
    public string $title,
) {}
```

Если выведенной колонки нет в схеме, сообщение об ошибке называет свойство и подсказывает про `#[JsonProviderColumn]`.

## Один DTO на таблицу

К таблице привязывается ровно один DTO-класс. Повторная регистрация того же класса — идемпотентный no-op; попытка привязать **другой** класс к той же таблице → `DtoAlreadyRegistered`: сначала снимите текущую привязку.

```php
$db->unregisterDto('users');            // снять привязку с таблицы
$db->registerDto(ArchivedUser::class);  // привязать другой класс
```

`unregisterDto()` принимает **имена таблиц** (не классы), можно несколько за вызов, и возвращает `$this`. Он громкий с обеих сторон: невалидное имя — например, случайно переданный `Foo::class` — отклоняется `InvalidTableName`, а таблица без привязки → `DtoNotRegistered`, чтобы опечатка не выглядела успешной операцией. Привязка — состояние процесса, а не схемы: на диске ничего не меняется, массивная поверхность работает как работала. Уже полученный хендл `table()` сохраняет карту, с которой был создан, — после перепривязки берите новый.

Привязка снимается и сама: `dropTable()` уносит её вместе с таблицей, а `renameColumn()` перекомпилирует DTO под новую схему и отвязывает несовпавший — тогда объектные чтения падают громким `DtoNotRegistered` вместо тихо сломанной гидрации.

## Enum

Свойство-backed enum хранится своим бэкинг-значением и собирается при чтении:

- **запись** — хранится `$status->value` (обычная `string`/`int`-колонка);
- **чтение** — `StatusEnum::from(<хранимое>)` восстанавливает кейс.

Хранимое значение без подходящего кейса бросает `InvalidEnumValue`. Поскольку nullability DTO обязана совпадать с колонкой, nullable-колонка требует nullable-свойства enum (`?StatusEnum`), и хранимый `null` чисто отображается в `null`.

> Если меняете контракт DTO (переименовали/убрали кейс enum, ужесточили nullability) — мигрируйте существующие значения в базе. Иначе чтение старых строк упадёт с `InvalidEnumValue` / `JsonProviderMappingException`.

## Объектные методы

```php
// insert — возвращает новый id (DTO не мутируется)
$id = $db->table('users')->insert(new User(
    id: 0,                       // игнорируется; назначается провайдером
    email: 'a@b.c',
    age: 30,
    status: StatusEnum::Active,
    createdAt: new \DateTimeImmutable(),
));

// selectOne — DTO или null
$user = $db->table('users')->where('id', '=', $id)->selectOne();

// selectAll — одноразовый генератор DTO (ленивая гидрация)
foreach ($db->table('users')->where('age', '>', 18)->selectAll() as $user) {
    // ...
}
// update — перезаписывает строку по собственному id из DTO всеми его полями
// (накопленный where() игнорируется — строку выбирает id, см. «Какие строки
// обновляются» в мутациях)
$db->table('users')->update($user);
```

`insert` возвращает `int`-id (как и `insertByArray`), а не объект — объект и так на руках. Частичный патч остаётся на массивной поверхности (`updateByArray(['age' => 31])`); `update($dto)` — перезапись всей строки, что ничего лишнего не стоит: запись всегда переписывается целиком.

Объектные методы принимают **любой объект**, класс не проверяется: значение берётся из свойства с тем же именем, что у зарегистрированного DTO, и проходит обычную валидацию колонки. Если у объекта нужного свойства нет (не объявлено или типизированное свойство не инициализировано):

- `insert` пишет в колонку `null` — для not-null колонки это `NullNotAllowed`;
- `update` по умолчанию делает то же (`MissingPropertyModeEnum::WriteNull`), а с `MissingPropertyModeEnum::KeepStored` колонку не трогает — в ней остаётся сохранённое значение. Явно присвоенный свойству `null` пишется в обоих режимах.

```php
use AV\JsonProvider\Mapping\MissingPropertyModeEnum;

// у Contact нет свойства phone — телефон в строке останется прежним
$db->table('users')->update($contact, MissingPropertyModeEnum::KeepStored);
```

Вызов объектного метода на таблице без зарегистрированного DTO бросает `DtoNotRegistered` — используйте `*ByArray`-двойник.
