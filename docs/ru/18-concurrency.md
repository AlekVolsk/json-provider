# Модель конкурентности

Внутри одного PHP-процесса: каждая запись в файл идёт через `flock(LOCK_EX)` на целевом файле. Никаких кросс-табличных транзакций и глобальной блокировки — параллельные записи в **разные** таблицы идут параллельно.

Между процессами: те же `flock`-семантики. Провайдер безопасен для малоконкурентного многопроцессного использования (классический mod_php / PHP-FPM с воркерами на разные запросы). Он **не рассчитан** на высокую конкуренцию или write-heavy параллельные нагрузки.

Кеш-слой работает по модели «invalidate on write»: любая DML через провайдер чистит кеш-запись затронутой таблицы. Если вы изменяете хранилище **в обход** провайдера — вызовите `$db->invalidateCache($tableName)`, чтобы кеш не врал.
