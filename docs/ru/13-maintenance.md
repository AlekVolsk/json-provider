# Сопровождение индексов и оптимизация таблицы

## Сопровождение индексов

Две операции для превентивного пересоздания индексов без удалить-и-создать:

```php
$db->table('products')->rebuildIndex('idx_category');
$db->table('products')->rebuildAllIndexes();   // включая PK
```

Обе атомарны на уровне файла (каждый файл индекса заменяется под эксклюзивной блокировкой). Используйте, если знаете, что индекс испорчен — например, после ручной правки файлов, или как периодическое обслуживание.

`rebuildIndex()` бросает `INDEX_NOT_FOUND`, если такого индекса нет в схеме таблицы.

Обе операции штампуют актуальный `indexFormat` в мете; `rebuildIndex()` на таблице со старым форматом эскалирует до перестройки всех индексов (см. [Индексы](06-indexes.md)).

## Оптимизация таблицы

```php
$db->table('products')->optimizeTable();
```

Тяжёлая обслуживающая операция:

1. читает все записи,
2. нормализует каждую по схеме (порядок ключей, отброс лишних, типовые дефолты для пропущенных колонок — `''`/`0`/`0.0`/`false`, `null` для nullable),
3. сортирует записи по `id` ASC,
4. перезаписывает файл данных,
5. пересоздаёт каждый индекс по новой укладке,
6. обновляет `meta.lineCount` до фактического числа строк.

Используйте периодически — после длинных delete-сессий или прямо перед бэкапом, чтобы поддерживать аккуратную раскладку на диске. Для штатной работы это не требуется.

Если в файле есть непарсимые NDJSON-строки, `optimizeTable()` отказывается его перезаписывать (перезапись молча уничтожила бы их): сначала разберите строки, которые `validate()` показывает находками `broken_record` — см. [Целостность](14-integrity.md).
