# Когда использовать (и когда нет)

**Подходит для** компактных хранилищ с низким трафиком, где полноценная СУБД избыточна:

- внутренние инструменты и админки с умеренным числом записей;
- конфиги с реляционной структурой;
- однопроцессные или малоконкурентные PHP-сервисы;
- прототипы, которые позже могут уехать на настоящую БД.

**Не подходит для** высоконагруженных по записи задач, больших датасетов, которые не помещаются в кеш, и сценариев со сложными join-ами, кросс-табличными транзакциями или строгой изоляцией. Для этого есть PostgreSQL, SQLite, MySQL, иные высоконагруженные СУБД.

Контракты провайдера специально узкие, чтобы миграция на настоящую СУБД позже была механической: первичные ключи, базовые foreign keys, индексы и привычный билдер запросов прозрачно ложатся в SQL.
